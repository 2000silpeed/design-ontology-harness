# Memory Garden — New Concept Pass

## Non-reuse boundary

This is a from-scratch concept pass. Do not copy or import:

- existing preset tokens or component specs;
- Orbit, LookMe, or other project screenshots;
- the VibeCoding motion reference pack;
- prior layout skeletons, card compositions, or visual reference images;
- competitor UI copy, data, or navigation taxonomy.

The harness provides only the authoring and validation machinery. Product identity,
information architecture, state vocabulary, and visual direction must be authored
here.

## Product premise

Memory Garden is a quiet temporal workspace for preserving thoughts and decisions
with the conditions that shaped them. It is not a task manager, journal feed,
calendar, or productivity scorecard.

The primary surface is a living timeline. Records are represented by semantic
states rather than decorative metaphors:

- `planted`: a new thought or decision has been placed;
- `tending`: the user is actively developing its context;
- `dormant`: the record is intentionally resting;
- `returned`: the user has revisited it and added what changed.

## Authoring order

1. Validate the product objects and care-state vocabulary.
2. Generate the system spec and ontology from this profile alone.
3. Review the first-screen contract before choosing visual polish.
4. Produce a minimal executable preview with real timeline states.
5. Run mobile, dark/light, keyboard, and reduced-motion verification.
6. Only after this pass decide whether external visual research is necessary.

## Success criteria

- The first screen reads as a temporal landscape, not a dashboard.
- A user can distinguish a Memory Seed from a Decision Stone without color alone.
- A Return Ritual has a visible reason and time context.
- The composition remains useful with zero records and with a dense season.
- No decorative garden motif appears unless it carries state or chronology meaning.
