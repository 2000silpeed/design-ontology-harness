# EKOS Knowledge Intake — 지식 등록·검토 워크벤치 Spec

> 원본 명세: Enterprise-knowledge-Operating-System/docs/04-product/knowledge-intake-screen-spec.md (v0, 2026-07-11)

## 제품 개요

EKOS Knowledge Intake는 SAP 업무 지식은 알지만 온톨로지·그래프 기술은 모르는 현업 사용자가
문서나 업무 설명을 넣고, 시스템이 이해한 사실을 고친 뒤, 승인된 지식의 근거를 확인하는
**데스크톱 웹 지식 등록·검토 워크벤치**다.

핵심 성격은 "그래프 관리 도구"가 아니라 **"업무 문장 중심의 사실 검토대"**다.
사용자는 ontology / fragment / node / edge / SHACL 같은 내부 어휘를 화면에서 보지 않는다.
대신 지식 체계 / 지식 초안 / 대상 / 관계 / 근거 / 검사 통과·확인 필요 같은 업무 표현만 본다.
IRI·CURIE·Pack·SHACL 리포트는 "고급 정보" 서랍에서만 원문으로 노출된다.

시각 정체성은 Prussian Blue(권위·집중) · Ocean Blue(신뢰) · Cornsilk(따뜻한 종이) 계열의
아카이브 감성을 유지하되, 지식 작성·검토 화면에서는 종이 질감보다
**읽기 쉬운 평면 배경과 넉넉한 여백**을 우선한다.
Rust는 승인·위험 의미로 쓰지 않고 강조에만, 성공은 Hunter Green, 경고는 Goldenrod,
실패·충돌은 Marsala가 맡는다. 한국어 UI가 1급이며 긴 문장, 표, 근거 비교가 많다.

## 사용자

- **현업 지식 제공자 (SAP 운영 담당자)**: 자기가 아는 절차·규칙·장애 해결을 문장으로 설명하거나 문서를 올리고, 시스템의 이해를 고쳐 승인까지 끝낸다. 온톨로지 용어를 모른다.
- **지식 검토자 (팀 리드)**: 검토함에서 `선택 필요`·`충돌 확인` 항목을 우선 처리하고, 근거와 원문을 대조해 승인·보류·제외를 결정한다.
- **운영 관리자**: 입력 작업 큐, 검증 실패·격리 항목, 연결 시스템 상태, 재시도를 한 화면에서 관리한다. 그래프 통계는 이 사람에게만 의미가 있다.

## 전체 흐름

홈 → 지식 추가(직접 설명 / 자료 올리기 / SAP 작업 가져오기 / 시스템 연결)
→ 분석 진행(5단계 문장형 진행 표시) → 지식 초안 검토(좌: 사실 목록, 우: 근거·수정)
→ (분기) 새 개념 제안 / 관계 연결 작업실 → 검토·승인 → 지식 상세.
사용자는 언제든 원문으로 돌아갈 수 있고, 분석 결과를 고쳐도 원문은 바뀌지 않는다.

## 핵심 화면

1. **홈** — 큰 통합 검색 입력 + 주 버튼 `지식 추가` + 보조 `SAP에서 가져오기` + 내가 확인할 항목(검토 대기 / 분석 실패 / 새 개념 답변 대기) + 최근 사용 지식. 그래프 통계 없음. 빈 상태에는 `샘플로 체험하기`(샘플과 회사 데이터를 색·라벨로 구분).
2. **지식 추가** — 네 가지 입력 방식 큰 목록. `직접 설명하기`는 큰 입력창 + 선택형 도움 틀(업무 절차/규칙/장애 해결/용어/데이터 흐름/관계) + 규칙 선택 시 세 가지 유도 질문. `자료 올리기`는 파일 메타 + 원문 보존·자동 공식화 안 됨·민감정보 격리 안내. 주 버튼은 `지식으로 정리하기`.
3. **분석 진행** — 5단계(원문 보관 → 문장·표 읽기 → 기존 지식 비교 → 확인 필요 탐지 → 초안 준비)를 완료/진행/대기 문장으로 표시. 실패 시 실패 항목별 `다시 시도`/`문제 항목만 제외`/`원문으로 직접 작성`/`운영 담당자에게 보내기`, 기술 예외는 "자세히 보기" 안에.
4. **지식 초안 검토** — 좌: 추출된 사실 목록 + 상태(`바로 확인 가능`/`선택 필요`/`새 개념 제안`/`충돌 확인`/`제외됨`), 초기 필터는 `선택 필요`+`충돌 확인`. 우: 선택한 사실의 업무 문장, 대상/조건/결과/적용 범위/유효기간 편집, 관계 후보 비교(문장형 + "왜 이 후보인가", 숫자 점수만 금지), 근거 패널(원문 발췌·매칭 키·추론 규칙·수정 이력). 하단: 보류/제외/수정 저장/선택 승인/검토 가능 전체 승인 + 반영 범위·개수 표시. 검증 실패 예상 항목은 승인 불가 + 이유 표시.
5. **새 개념 제안** — 현업 이름/뜻·사용 예/비슷한 기존 용어/사용 업무/대기 중 지식 목록만 입력. 내부 Core 종류·Pack·제약 후보는 고급 보기. 제출 후 "공식 지식 체계 검토 중" 상태 + 담당자 + 다음 단계.
6. **관계 연결 작업실** — 검색 결과를 작업 공간에 놓고 선으로 연결. 키보드 대안 경로(`연결 시작`→검색→`연결 후보 보기`). 연결 직후 점선 `분석 중`, 본 그래프에는 쓰지 않음. 결과 6종(동일 대상/동일 후보/기존 경로/직접 관계 후보/중간 단계 필요/근거 부족). 방향·관계 문장·범위·근거 수정 후 검토함으로.
7. **지식 상세** — 업무 문장 요약 → 상태(초안/확인 필요/팀 확인/공식/철회됨) → 핵심 근거 → 연결 대상·영향 → 변경·승인 이력 → 고급 보기(그래프·IRI·Pack·SHACL). `왜?`/`어디서 왔나?`/`무엇이 영향 받나?` 즉시 실행, 결과는 문장·단계 목록 우선, 그래프는 보조.
8. **운영 상태** — 입력 작업 대기/진행/성공/실패, 검증 실패·격리, 재시도(중복 생성 금지, 기존 작업의 새 시도임을 구분), 연결 시스템·인덱스 동기화·백업 상태, 권한 차단 작업.

## UI 컴포넌트 (도출)

- **global-search-input** — 홈·상단 통합 검색. 업무 질문 문장을 받는 큰 입력
- **intake-method-list** — 네 가지 입력 방식의 큰 선택 목록 (아이콘 + 설명 + 예시)
- **describe-composer** — 직접 설명하기 대형 자유문장 입력창 (한글 IME keep-all, 표 붙여넣기 허용)
- **help-frame-selector** — 업무 절차/규칙/장애 해결/용어/데이터 흐름/관계 도움 틀 선택 칩
- **guided-question-strip** — 규칙 선택 시 입력창 위 세 질문(조건/결과/확인 위치) 안내 줄
- **upload-manifest-card** — 파일 이름·형식·크기·보안 범위 + 원문 보존/비공식/격리 안내 3줄
- **analysis-stage-list** — 5단계 문장형 진행 표시 (완료/진행/대기, 회전 표시 단독 금지)
- **analysis-failure-panel** — 실패 파일·구간 목록 + 4가지 복구 행동 + 기술 예외 접기
- **fact-list-row** — 추출된 사실 한 줄 (업무 문장 요약 + 상태 태그 + 근거 개수)
- **fact-status-tag** — `바로 확인 가능`/`선택 필요`/`새 개념 제안`/`충돌 확인`/`제외됨` 상태 태그 (색+아이콘+텍스트, 색 단독 금지)
- **fact-filter-bar** — 상태 필터, 초기값 `선택 필요`+`충돌 확인`
- **fact-sentence-editor** — 한 문장 기본 표시 + 대상/조건/결과/적용 범위/유효기간 필드 편집
- **relation-candidate-card** — 관계 후보 비교 카드 (업무 문장 + "왜 이 후보인가" 근거 줄, 숫자 점수 단독 금지)
- **evidence-panel** — 우측 근거 패널: 원문 발췌 + 위치, 매칭 키, 추론 규칙, 사람 수정 이력
- **source-compare-view** — 원문과 구조화 문장의 좌우 대조 보기
- **review-action-bar** — 보류/제외/수정 저장/선택 승인/전체 승인 + 반영 범위·개수 + 승인 불가 사유
- **new-concept-form** — 현업 이름/뜻·예시/유사 용어/사용 업무 입력 + 대기 지식 목록
- **concept-review-status** — "공식 지식 체계 검토 중" 상태 + 담당자 + 예상 다음 단계
- **link-workspace-canvas** — 관계 연결 작업 공간 (검색 결과 배치 + 선 연결 + 점선 분석 중)
- **link-keyboard-flow** — `연결 시작`→대상 검색→`연결 후보 보기` 키보드 대안 경로
- **link-verdict-card** — 연결 분석 결과 6종 카드 (동일/후보/기존 경로/직접/중간 필요/근거 부족)
- **knowledge-status-badge** — 초안/확인 필요/팀 확인/공식/철회됨 수명주기 배지
- **provenance-timeline** — 변경·승인 이력 타임라인 (누가·언제·무엇을·왜)
- **impact-question-buttons** — `왜?`/`어디서 왔나?`/`무엇이 영향 받나?` 즉시 실행 버튼
- **advanced-drawer** — 고급 보기 서랍: 그래프·IRI·Pack·SHACL 리포트 원문
- **ops-queue-table** — 운영: 입력 작업 대기/진행/성공/실패 테이블 + 재시도(중복 방지 표시)
- **quarantine-list** — 검증 실패·격리 항목 목록 + 실패 원인 + 재시도 가능 여부
- **sample-data-badge** — 샘플 데이터와 회사 데이터를 구분하는 라벨
- **empty-state-guide** — 첫 사용 빈 상태: 안내 문장 + `샘플로 체험하기`
- **left-nav** — 홈/검색/지식 추가/검토함/영향과 원인/관리 좌측 메뉴
- **workspace-topbar** — 현재 작업공간 + 통합 검색 + 도움말 + 사용자 메뉴

## 공통 상태

모든 주요 화면에 첫 사용 빈 상태 / 분석 중 / 일부 성공 / 검증 실패 / 권한 없음 /
원본 변경 재검토 필요 / 네트워크 끊김 / 백그라운드 전환을 설계한다.

## 접근성·타이포 기준

- WCAG 2.2 AA, 모든 핵심 과업 키보드 완료, canvas 그래프의 목록·표 대체 제공
- 포커스 이동·상태 변경 보조기기 알림, 애니메이션 줄이기 설정 지원
- 본문 14~16px, 긴 설명은 편안한 줄 길이(65~75ch), 색만으로 상태 구분 금지
- `수정`/`승인`/`철회` 버튼 근처에 결과와 영향 범위 명시

## 수용 과업 (프로토타입 테스트)

Word 문서 추가 → `선택 필요` 항목 찾기 → 관계 후보 비교·선택 → 새 개념 제안 →
검토 가능 항목만 승인 → 지식 상세에서 원문·승인자 확인 → 검색 결과 두 개 연결 후 검토함 전송.
사용자가 온톨로지 용어 설명 없이 이 과업을 끝낼 수 있어야 한다.
